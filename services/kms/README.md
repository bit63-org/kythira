# KMS module

A KMS-compatible key management service for Kythira: AWS KMS's JSON 1.1 API
(`TrentService`), so the AWS CLI, the SDKs and the AWS Encryption SDK work
against it unchanged. It holds no key material itself: every key's material
is a non-extractable object on the virtual HSM's `kms` token
(`services/hsm/`), and every request is authorized by IAM with the key's
policy (`services/iam/`). Like the HSM it is software, so key material is in
host memory while in use (`doc/hsm.md`). The spec is
`.kiro/specs/kms-compatible-api/`; this directory follows
`services/README.md`.

Built when `CONFIG_KMS=y` (`services/kms/Kconfig`, off by default, needs
`CONFIG_HSM` and `CONFIG_IAM`). `configs/ci_full_defconfig` turns it on, so
ci.yml builds and tests it; `configs/ci_no_kms_defconfig` is the module-off
configuration `.github/workflows/kms-module.yml` checks.

## What is here

| Path | What | Task |
|---|---|---|
| `model/service-2.json` | botocore 1.43.100's `kms` model, unchanged, with botocore's `LICENSE` and `NOTICE` | 1 |
| `include/kythira/kms/model/kms_model.hpp` | the model's shapes and operations as `constexpr` tables for core's `raft/aws_json_protocol.hpp`, generated by `scripts/gen_aws_json_shapes.py` | 1 |
| `implemented-operations.txt`, `doc/unsupported.md` | every model operation, implemented or listed with its planned task, reason and error; `tools/check_coverage.py` keeps the two complete | 1 |
| `cmd/kms_node/` | the daemon; a placeholder (`--help`, `--self-test`) until task 12 | 1 |
| `tests/` | `kms_model_coverage` and its checker's fixture tests, `kms_model_header_fresh` (the header matches the model), `kms_model_test` (the tables validate requests) and `kms_node_self_test` | 1 |

The action table, ciphertext format, catalog, HSM binding, the API, grants,
rotation, the daemon and the Kinesis and DynamoDB integrations follow in
tasks 2 to 20 (`.kiro/specs/kms-compatible-api/tasks.md`).

## Core targets and variables used

This is the list a split into its own repository would need a Kythira
package to export.

| From core | Used for |
|---|---|
| `kythira_core_headers` | `include/` and `generated/` (`raft/aws_json_protocol.hpp`), through `kythira_kms` |
| `boost_json` | the model's codec, through `kythira_kms` |
| `OpenSSL::Crypto` | the ciphertext format and request signing to come, through `kythira_kms` |
| `KYTHIRA_AWS_JSON_SHAPES_GENERATOR` | `kms_model_header_fresh` regenerates the shape tables with it |
| `kythira_test_pch` | the guard the tests are entered under, and what the C++ tests link |
| `cmake/kythira_test_helpers.cmake` | `add_raft_completion_test`, `kythira_scale_test_timeouts` |

## What a split would still need

Nothing beyond the table above yet. The module includes no core
`*_impl.hpp` header (`boundary-allow.txt` is empty) and no other module.
